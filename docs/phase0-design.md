# 研钟 Phase 0 实施设计

- 日期：2026-09-25
- 状态：实施完成，待线上域名切换与最终验收
- 范围：代码、协议页面、运维脚本与部署准备
- 最新核验：服务端测试 60/60 通过，Prisma schema 校验通过；Android 计划展示与运维脚本已落地，Android 构建需复跑确认

## 目标

Phase 0 的目标是让新用户能够完成首次备考配置并获得一份可执行的动态计划，同时为公开使用补齐基础协议、数据权利和服务器运维准备。AI 不作为本阶段运行依赖，现有 468 天静态计划继续作为兜底能力。

## 范围

### 服务端

新增服务端权威的备考档案与计划资源：

- `user_profiles`：目标类型、考试日期、每日可用时长、基础情况、薄弱科目、问卷完成状态。
- `plans`：用户当前计划、计划类型、起止日期、来源、状态和版本。
- `plan_stages`：基础、强化、冲刺等阶段及日期范围。
- `plan_items`：阶段内可执行的学习安排，包含科目、标题、日期、时长、优先级和完成状态。

这些资源不加入现有 `clientGuid` 墓碑同步协议，服务端作为权威来源，通过独立 API 读取和更新。生成失败时必须返回可识别错误，并由客户端回退到静态 468 天计划，不得产生半成品计划。

### Android 客户端

新增登录后的首次使用网关：

1. 检查服务端备考档案。
2. 未完成时展示紧凑问卷。
3. 保存问卷并请求规则版计划生成。
4. 生成成功后进入现有计划页。
5. 网络失败或生成失败时保留本地 468 天计划，并提供稍后重试入口。

问卷收集：备考目标、考试日期、每日可用时长、固定学习时段、基础情况和薄弱科目。老用户不强制重新填写，已有本地计划不被覆盖。

### 协议与数据权利

新增隐私政策和用户协议页面，并在注册流程中增加确认项。增加数据导出与账号注销入口，注销需要二次确认并调用服务端删除或匿名化接口；导出沿用现有全量 JSON 能力并明确导出范围。

### 运维

新增每日 MySQL 备份脚本和恢复演练脚本，包含：

- 按日期命名备份文件；
- 保留周期参数；
- 失败退出码和日志；
- 恢复前明确禁止覆盖生产数据的演练方式；
- 与现有 Docker Compose 命名卷兼容。

新增域名 + 反向代理 + HTTPS 配置模板和切换说明。当前 IP + HTTP 内测期间保持 `TRUST_PROXY=false`，正式切换后再启用反代信任配置。实际服务器执行需要用户提供服务器登录条件和域名控制权。

## 数据流

```text
登录
  -> GET 备考档案
  -> 未完成：提交问卷
  -> POST 规则计划生成
  -> 服务端事务创建 plan/stages/items
  -> 客户端拉取计划
  -> 进入现有计划与专注流程
```

执行数据继续使用现有同步链路：`subjects`、`tasks`、`sessions` 和复盘资源不改变协议。计划数据只通过计划 API 交互，避免两套一致性模型相互污染。

## 错误处理

- 未登录或令牌失效：沿用现有认证刷新机制。
- 问卷字段不完整：服务端返回字段级校验错误，客户端保留输入内容。
- 考试日期不合法或已过期：禁止生成并提示修改。
- 计划生成异常：服务端事务回滚，客户端使用静态计划并显示重试操作。
- 网络不可用：允许继续使用本地已有计划和计时能力。
- 删除或导出失败：保留数据，不显示成功状态，提供重试。

## 兼容性

- 不迁移或删除现有 12 张 Prisma 表。
- 不改变 Room v6 现有实体和同步协议。
- 不改变现有登录、WebSocket、专注守护和 468 天计划包。
- 新用户流程通过状态判断接入，老用户继续进入原主界面。
- 数据库变更使用现有容器启动时的 Prisma schema 同步方式，并在部署前执行备份。

## 验收标准

- 新用户可注册、登录并完成问卷。
- 服务端可保存和读取用户档案。
- 根据考试日期生成阶段和计划项，且生成过程原子完成。
- 多设备登录可读取同一份服务端计划。
- 老用户和已有本地计划不受影响。
- 计划生成失败时可回退到 468 天静态计划。
- 注册流程展示并确认协议。
- 用户可导出数据并发起注销。
- 每日备份脚本可执行，恢复演练命令可执行。
- HTTPS 配置模板和服务器切换步骤完整，但在没有服务器登录权限时不宣称线上切换已完成。

## 明确不做

- 本阶段不接入大模型。
- 本阶段不开放考公、法考等复杂目标的专属计划规则，只保留目标类型可扩展字段。
- 本阶段不改造现有番茄钟同步协议。
- 本阶段不公开分发当前 IP + HTTP 内测 APK。
