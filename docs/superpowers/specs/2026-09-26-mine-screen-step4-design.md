# Step 4：个人界面重构设计

## 背景

产品演进方案中的 Step 4 要求重写 `MineScreen`，形成学习档案、账号与安全、偏好设置三个主要区块。当前页面已经包含主题、番茄方案、专注偏好、科目管理、备份导入、账号安全等功能，但学习档案信息仍主要分散在页面顶部和统计页，缺少统一的个人概览。

本次改造只针对 Android 客户端个人页，不新增服务端接口，不改变现有同步协议和数据库表结构。

## 目标

1. 将 `MineScreen` 重组为清晰的三块主内容：学习档案、账号与安全、偏好设置。
2. 在学习档案中展示累计专注时长、连续打卡天数、科目投入分布、效率节律，并提供最近 7 天趋势摘要。
3. 让学习档案与统计页使用同一套 `pomodoro_session` 有效会话口径，避免数字不一致。
4. 保留现有数据导出、账号注销、主题、番茄方案、声音震动、专注模式、科目管理和本地备份导入能力。
5. 通过 ViewModel 层测试覆盖核心统计计算和空数据状态。

## 非目标

- 不把计划资源落地到本地 `subjects`/`tasks`。
- 不新增服务端统计接口或改变服务端 API。
- 不实现 AI、周报月报、动态计划重排。
- 不在本轮引入新的图片资源、主题体系或导航目的地。
- 不重复实现统计页的完整图表；个人页只展示摘要信息。

## 页面结构

`MineScreen` 采用单列滚动布局，保持现有最大宽度和沉浸式头部。头部保留用户概览、累计专注天数和连续打卡信息，正文按以下顺序组织：

1. **学习档案**：四项核心指标、科目投入摘要、效率节律摘要、近 7 天趋势摘要。
2. **账号与安全**：账号状态、服务端数据导出、账号注销；沿用现有确认流程和错误提示。
3. **偏好设置**：主题、番茄方案、声音与震动、静默模式、连续专注、自动接力、周目标和每日番茄目标。
4. **数据与其他**：科目管理、本地备份与导入、关于等现有低频操作，作为次级区域保留。

页面不增加新的深层导航。学习档案区中的摘要内容点击后可进入现有统计页；若当前导航结构不适合直接跳转，则先保持只读展示，不为此扩展导航范围。

## 数据与口径

### 共享统计模型

新增一个与 UI 无关的学习档案数据模型，建议放在统计相关的数据层或独立的共享包中。模型至少包含：

- `totalFocusMin`：所有 `valid = 1` 会话的 `durationMin` 总和。
- `activeDays`：存在有效会话的本地自然日数量。
- `streakDays`：复用现有 `streakDays(activeDays)` 算法。
- `perSubject`：按 `subjectId` 汇总有效会话分钟数，并关联当前科目名称和颜色。
- `peakHour`：按本地小时汇总有效会话分钟数，取总分钟数最高的小时；无数据时为空。
- `recentDaily`：最近 7 个本地自然日的有效专注分钟数，包含没有记录的日期并填 0。

所有会话统计必须过滤 `valid = 1`。日期和小时均使用设备当前 `ZoneId`，与现有统计页保持一致。没有会话时，指标显示明确的零值或空状态，不使用虚假示例数据。

### 复用原则

优先复用 `StudyRepository` 和 `SessionDao` 已有的会话查询及 `StatsViewModel` 当前口径。若现有查询不足以支持最近 7 天或峰值时段，则增加仓库层 Flow 或纯 Kotlin 聚合函数，不在 Composable 中直接访问数据库。

`MineViewModel` 负责将共享统计模型与设置、科目列表组合为 `MineUiState`。`MineScreen` 只负责渲染状态和触发已有操作。

## 交互与状态

- 学习档案实时响应本地会话、科目和同步数据变化。
- 数据导出与账号注销继续使用现有系统文件选择器、二次确认和 Toast 反馈。
- 偏好设置继续调用现有 `MineViewModel` 写入方法。
- 科目管理、本地导入导出等已有弹窗行为保持不变。
- 长文本、空数据和无科目场景必须可正常布局，不得挤压或遮挡其他区块。

## 测试与验收

### 单元测试

至少覆盖：

- 空会话列表返回零时长、零天数、空科目分布、空峰值时段。
- 多条有效会话正确累计总时长和活跃天数。
- `valid = false` 的中断会话不计入任何学习档案指标。
- 科目分钟数正确聚合并按投入量排序。
- 峰值小时取累计分钟最多的小时。
- 最近 7 天包含无记录日期，并按本地日期升序排列。
- 连续天数与统计页现有算法一致。

### 构建与回归

- Android debug 编译通过。
- 现有 Mine、Stats、Focus 相关测试不回归。
- 账号导出、账号注销、主题和专注设置操作仍可用。
- 在窄屏和大屏宽度下，三个主区块均能完整显示。

### 完成标准

Step 4 只有在以下条件同时满足时才标记完成：

1. `MineScreen` 已按三个主区块完成重组。
2. 学习档案四项核心数据和最近 7 天摘要已接入真实本地数据。
3. 学习档案与统计页的有效会话口径一致。
4. ViewModel 或统计聚合测试覆盖上述边界。
5. Android debug 构建和相关回归验证通过。

## 实施顺序

1. 抽取或补齐共享学习档案统计模型与仓库查询。
2. 为统计模型添加测试，并验证与现有统计页口径一致。
3. 扩展 `MineUiState` 和 `MineViewModel`。
4. 重组 `MineScreen` 三个主要区块，迁移现有控件，不改变业务行为。
5. 运行 Android 编译和相关测试，修复回归后更新 Step 4 验收记录。
