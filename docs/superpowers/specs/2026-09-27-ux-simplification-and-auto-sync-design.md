# 主要页面体验简化与自动同步设计

## 背景

当前 Android 客户端已经具备登录后自动增量同步能力（`DataSyncer`：本地改动 3 秒防抖、设置改动 5 秒防抖、他端通知 1 秒防抖、每 15 分钟一轮），也具备设置 KV 同步、全量备份/恢复和 WebSocket 变更通知。服务端接口已经能满足同步需求。

问题不在能力缺失，而在界面把实现细节直接暴露给了普通用户：

- “我的”页需要用户理解服务器地址、增量同步、全量备份、覆盖恢复、WebDAV、导出全量 JSON、批量导入 JSON、导出服务器存档等概念，而这些入口分散在不同位置，用户很难判断“我到底要不要备份、备份到哪”。
- “我的”页头部写死“考研人 · 软件工程”和“408 + 数学二 + 英语二 + 政治”，与用户实际配置的科目可能不一致。
- 首页把复盘入口放在今日待办之前，添加任务入口在最底部。
- 专注页空闲态把模式、方案、两个开关放在“开始专注”之前。
- 统计页存在范围筛选，但趋势、时段、热力图各自使用固定窗口，筛选后无法判断哪些数据受筛选影响。
- `DataSyncer` 的 `stop()` 只把 `started` 置否，不取消已启动的协程；重复退出登录/重新登录会累积多个周期同步循环。另外切换账号时同步水位没有重置。

本轮只做定点改造：收敛“我的”页、让同步对普通用户零配置、修正上述页面问题。不重做导航、不重新设计同步协议、不引入新的数据格式。

## 目标

1. 普通用户登录后自动同步，日常不需要做任何同步配置。
2. “我的”页只保留常用偏好与同步状态；技术性数据和账号操作收进一个次级页面。
3. 首页优先呈现今日待办；专注页空闲态优先呈现开始专注；统计页让筛选口径与图表标注一致。
4. 修复 `DataSyncer` 生命周期与账号切换水位问题，保证自动同步可靠。
5. 保留全部现有能力，仅调整入口位置、默认可见性和文案。

## 非目标

- 不新增同步协议、不改变资源清单与 `since` 水位机制。
- 不实现应用被杀死后的后台周期同步（不引入 WorkManager）。下次打开应用时会自动补齐。
- 不自动上传全量备份；全量备份保持按需触发。
- 不改变专注计时规则，不改变严格模式紧急退出的次数限制。
- 不重做整体导航结构与视觉主题。

## 已确认的决策

| 议题 | 决策 |
| --- | --- |
| 同步策略 | 登录后自动同步，普通用户零配置；服务器地址与同步频率不出现在常规流程，手动同步降级为次级入口 |
| 全量备份 | 仅按需；不做自动云端快照 |
| 改造范围 | 覆盖首页、专注、统计、我的四个主要页面 |
| 专注退出 | 只改文案，保留现有次数限制 |
| 数据管理入口 | 收进“数据与账号”次级页面，保留导出、恢复、WebDAV、注销 |
| 后端改动 | 本轮不需要新增接口 |

## “我的”页设计

### 页面结构

单列滚动，保持现有沉浸式夜空头部与白色圆角面板，正文顺序调整为：

1. **同步状态卡**（新增，置顶）
2. **偏好设置**：主题、番茄方案、专注偏好、每周学习目标、每日番茄目标
3. **科目管理**：科目列表、添加、批量添加、删除
4. **数据与账号**（入口项）：进入次级页面
5. **关于**

原有“账号与安全”“数据与其他”“备份与导入”三个区块从主页移除，内容迁移到次级页面。

### 头部

- 去掉硬编码的“考研人 · 软件工程”和“408 + 数学二 + 英语二 + 政治”。
- 主标题显示当前账号用户名；未登录时显示“本机学习档案”；已登录但本地尚未保存用户名（升级前的旧登录状态）时显示“已登录”。
- 副标题由 `state.subjects` 动态拼接，最多显示 4 个科目名，超出追加“等 N 科”；无科目时显示“尚未设置科目”。
- 保留“共专注 N 天”“连续打卡 N 天”两个标签。

### 同步状态卡

一张卡片承载全部同步感知，用户不需要进入任何页面就能知道数据是否安全。

未登录：

- 文案：“数据只保存在本机”
- 说明：“登录后自动同步，换设备或重装可恢复。”
- 主按钮：“登录并开启同步” → 跳转 `Routes.CLOUD`
- 附一条弱化文字：“不登录也可以正常使用，数据不会丢失。”

已登录：

- 首行显示用户名与“自动同步已开启”。
- 状态行三态：
  - 运行中：“正在同步…”
  - 成功：“已同步 · 刚刚 / N 分钟前 / 今天 HH:mm / M月d日 HH:mm”
  - 失败：“同步遇到问题” + 原因摘要 + “重试”文字按钮
- 失败原因使用可理解措辞：网络不可用、登录已过期（需重新登录）、服务器暂时不可用；不展示 HTTP 状态码或异常类名。
- “立即同步”作为卡内右上角次级文字按钮保留，不做主按钮。

### 次级页面：数据与账号

新增路由 `Routes.DATA = "mine_data"` 与 `MineDataScreen`，复用现有 `MineViewModel`。页面分组如下：

1. **云端同步**：入口进入 `Routes.CLOUD`，用于登录、设备管理、专注接力、退出登录。
2. **手动备份**
   - “备份当前设备数据到云端”
   - “从云端恢复到本机”（保留覆盖确认弹窗与后果说明）
3. **文件导入导出**
   - “导出全量 JSON”
   - “批量导入 JSON”
4. **其他云盘**：WebDAV 入口进入 `Routes.WEBDAV`。
5. **账号**
   - “导出服务器存档”
   - “注销账号”（保留现有的两步确认与用户名+密码校验）
   - 隐私政策等协议链接
6. **服务器地址**（高级，默认折叠）
   - 默认展示“已使用内置服务器”，展开后才能查看与修改地址
   - 仅在连接本地或调试服务器时使用

普通用户在该页只需要认识“云端同步”和“手动备份”两组；服务器地址与 WebDAV 属于高级项。

## 同步行为设计

### 客户端

- 登录成功后自动启动同步：保留现有 `authState` → `dataSyncer.start()` 联动。
- 登录后首次同步沿用现有逻辑：先推本地待同步数据，再按 `since` 拉取云端变更。
- 未登录时不启动同步，数据全部保留在本机。
- 退出登录时停止同步，但不清理本地学习数据。

### 需要修复的实现问题

1. **协程泄漏**：`DataSyncer.start()` 每次调用都会新开 4 个长期收集协程（脏数据信号、WebSocket 通知、设置推送、15 分钟周期循环）。`stop()` 只把 `started` 置否而不取消它们，重复登录会累积多个周期循环。修复方式：把这些协程的 `Job` 汇总到一个父 `Job`，`stop()` 时取消父 Job 并置空，`start()` 时重建。
2. **切换账号水位未重置**：登录到不同 `user.guid` 时，`SINCE_KEY` 与 `SETTINGS_SYNC_KEY` 仍是上一个账号的水位，`lastAppliedRemote` 仍缓存上一账号的设置快照，可能导致漏拉或设置被旧值覆盖。修复方式：在检测到账号切换时（沿用 `CloudSyncViewModel.login` 中已有的 `previousAccount != resp.user.guid` 判断）清空两个水位与 `lastAppliedRemote`，同账号重新登录则保留水位以免重复全量拉取。
3. **上次同步时间未持久化**：`TokenStore.saveLastSync` / `currentLastSync` 已存在但无人调用，应用重启后“上次同步”归零。修复方式：`DataSyncer` 同步成功后写入，失败不改写；“我的”页读取它作为初始值，再用内存中的实时状态覆盖。
4. **登录用户名未保存**：`TokenStore` 未保存用户名，“我的”页无法展示账号。修复方式：登录成功时把 `resp.user.username` 写入本地偏好；退出登录或切换账号时清除。

### 明确不做

- 不引入 WorkManager 或后台任务调度：应用进程存活期间同步照常运行（含后台），进程被杀后不再同步，下次启动立即补齐。这符合“不要搞那么复杂”，也避免额外的电量与系统权限成本。

## 首页设计

保持现有数据与交互逻辑，只调整顺序与默认展开状态：

1. 顺序改为：页面头部 → 阶段条 → 今日节奏 → **今日待办** → 快速开始/添加任务 → 复盘卡。
2. 页面头部右侧增加“＋ 添加任务”入口，不再只能靠底部快速开始栏触发。
3. “今日节奏”默认收起为一行概览（计划名 + 进度），点击展开各时段明细，降低首屏密度。
4. 复盘卡保持在待办之后；周/月复盘入口的显示条件沿用现有逻辑，不在本轮改动。

## 专注页设计

1. 空闲态顺序改为：**今日任务（可一键开始）** → 自由专注入口 → 模式与番茄方案的紧凑选择行 → 折叠的“更多设置”（自动串联、连续专注、静音、震动、音效）。
2. 已选任务后“开始专注”保持在首屏可见位置。
3. 文案调整（规则不变）：
   - 非严格模式下把当前显示为“紧急退出”的操作改为“结束专注”。
   - 严格模式保留“紧急退出”，并在提示中说明该模式下方才受限，普通模式可随时结束。
   - 次数提示明确归属：“本月紧急退出剩余 N 次（仅严格模式）”。
4. 计时运行态的按钮、二次确认与 Toast 逻辑不变。

## 统计页设计

1. 筛选行文案调整为“小结范围”，并在其后增加一行说明：“筛选作用于上方小结与科目占比；下方长期图表各自标注统计窗口。”
2. 新增分组标题“长期趋势（不随小结范围变化）”，把趋势、24 小时时段、周几分布、打卡热力图归入该分组。
3. 统一各图表标题格式，窗口信息前置且措辞一致：
   - 净专注趋势 · 近 14 天
   - 24 小时时段分布 · 近 30 天
   - 一周节奏 · 周几分布
   - 打卡热力图 · 近 15 周
4. 累计纪录卡标题明确为“累计纪录”，与区间小结区分。
5. 不改动各图表的查询窗口与统计口径，不改动 `StatsViewModel` 的聚合逻辑；本轮只解决“筛选范围不明确”的认知问题。

## 数据与口径

- “我的”页同步状态来自 `DataSyncer.state`（`running` / `lastSyncAt` / `lastError` / `pushed` / `pulled`）与 `TokenStore` 的登录态、用户名、持久化上次同步时间。
- `MineUiState` 增加 `loggedIn: Boolean`、`username: String`、`sync: SyncState` 三个字段，由 `MineViewModel` 组合现有数据源得到，`MineScreen` 只负责渲染。
- 学习档案、科目、专注天数等口径保持不变，继续使用现有 `LearningProfile` 与有效会话过滤规则。

## 交互与状态

- 同步失败不阻断任何学习操作，只更新同步状态卡文案。
- 未登录→登录、登录→退出、切换账号三种状态切换后，同步状态卡立即反映当前状态。
- 次级页面的导入、导出、恢复、注销继续复用现有系统文件选择器、结果提示与二次确认，不新增反馈方式。
- 所有新增文案使用中文，避免出现“增量”“水位”“回声”等实现术语。

## 验收标准

1. 空数据状态下“我的”页正常显示，未登录时同步卡展示“数据只保存在本机”与登录入口。
2. 登录成功后无需任何额外操作，同步卡依次出现“正在同步…”与“已同步”状态；本地新增一条任务后，无需手动操作即可在状态卡看到同步完成。
3. 切换账号后不出现漏拉：新账号首次同步能拉到云端全部数据；旧账号设置不会覆盖新账号。
4. 连续执行 3 次退出登录并重新登录，周期同步仍只运行一份（不出现同步频率成倍增加）。
5. 应用重启后同步卡仍能显示上次成功同步时间。
6. “我的”页主页不再出现服务器地址、WebDAV、导出 JSON、批量导入、注销账号等入口，均可在“数据与账号”页找到。
7. 头部科目信息与实际科目列表一致。
8. 首页首屏可见今日待办，添加任务入口在头部即可触达。
9. 专注页空闲态首屏可直接开始今日任务。
10. 统计页在四种小结范围下，图表归属分组与窗口标注清晰，无“筛选了但图表不变”的困惑。
11. 严格模式紧急退出次数限制与行为保持不变；非严格模式结束操作文案为“结束专注”。
12. `./gradlew :app:compileDebugKotlin` 通过；服务端无改动。

## 服务端

本轮不需要新增或修改服务端接口。现有的 `POST /api/v1/sync/:resource`、`GET /api/v1/sync`、`GET/PUT /api/v1/settings`、`GET /api/v1/backup`、`POST /api/v1/backup/restore`、`GET /api/v1/account/export` 以及 WebSocket 通知已覆盖全部需求。账号名改为本地持久化，不新增 `/me` 接口，保证离线可用。

## 风险与取舍

- 统计页选择“标注口径”而非“重做联动查询”，避免了改动四个数据窗口带来的回归风险，代价是筛选不再改变图表窗口，需要用分组标题和说明明确表达。
- 不做后台任务调度意味着应用进程被杀后不会同步，用户需在下次打开应用时补齐。这是本轮刻意的简化，若后续确有必要再单独评估。
- “我的”页新增一个次级页面，页面数量增加，但主页认知负担显著下降。
