# 专注模式应用内锁定设计

## 背景

专注计时已经具备番茄钟状态机、前台服务、常驻通知、持久化和恢复能力。本次改造聚焦于用户体验：专注开始后进入应用内严格专注界面，减少误触退出和页面切换，同时保持后台计时行为不变。

## 目标

- 专注运行期间隐藏底部导航，避免直接切换到其他页面。
- 拦截系统返回，避免误触退出专注页面。
- 专注页面进入时保持屏幕常亮，离开页面后恢复系统默认行为。
- 保留暂停、继续、跳过休息和长按放弃能力。
- 放弃专注必须经过长按和二次确认。
- 切到后台、熄屏或进程恢复时，计时继续依赖现有引擎和前台服务。
- 明确不实现系统级禁止 Home、任务切换或打开其他应用。

## 方案

采用应用内锁定，不新增设备管理员、无障碍服务或 kiosk 权限。导航层根据计时状态决定是否展示底部导航：`TimerState.isRunning == true` 时隐藏导航，回到 `IDLE` 后恢复。专注页面使用 Compose 返回拦截器消费返回事件；若用户需要退出，必须通过页面上的长按放弃入口，并在确认弹窗中再次确认。

屏幕常亮由专注页面生命周期控制。页面进入运行态时为宿主窗口添加 `FLAG_KEEP_SCREEN_ON`，页面离开或计时回到空闲时清除该 flag，避免影响首页、计划页等其他页面。该能力仅保证应用处于前台时保持亮屏，不阻止用户主动锁屏。

## 交互流程

1. 用户开始自由专注或任务专注。
2. 页面进入严格专注态，隐藏底部导航并保持屏幕常亮。
3. 用户可暂停或继续计时；休息阶段可跳过休息。
4. 用户按系统返回时不离开专注页，可通过轻提示说明“专注进行中，请长按放弃”。
5. 用户长按“放弃专注”达到现有 1.5 秒阈值后，打开确认弹窗。
6. 用户确认后调用现有 `abandon()`，引擎清理计时状态并恢复普通导航。
7. 专注自然结束或流程回到 `IDLE` 后，清除常亮标记并恢复底部导航。

## 代码边界

- `AppNav.kt`：根据共享的 `TimerState` 控制底部导航显示，不改变现有路由结构。
- `FocusScreen.kt`：增加返回拦截、窗口常亮生命周期处理、退出确认弹窗，并保持已有计时操作。
- `MainActivity.kt`：仅在现有窗口环境不足时提供必要的窗口访问支持；优先不增加全局常亮逻辑。
- `FocusViewModel.kt`：若页面需要统一封装放弃操作，可增加薄包装方法；不复制计时状态机逻辑。
- `PomodoroEngine.kt` 与 `FocusService.kt`：不改变计时算法、持久化恢复和通知机制。

## 状态与异常处理

- 以 `timer.phase != Phase.IDLE` 作为是否锁定的单一事实来源，暂停和休息阶段仍属于锁定态。
- 页面重组不应触发重复计时或重复启动服务。
- 页面销毁时必须清除窗口常亮标记，避免 Activity 生命周期异常导致全局常亮。
- 弹窗确认前不调用 `abandon()`；取消弹窗保持当前计时状态。
- 系统返回只消费事件，不修改引擎状态。
- 不对 Home、系统任务切换、通知栏或其他应用做拦截承诺。

## 验证

- 静态检查：确认运行专注时底部导航不渲染，空闲时恢复渲染。
- 静态检查：确认返回拦截只在非空闲阶段启用。
- 静态检查：确认常亮 flag 在进入和离开运行态时成对设置和清除。
- 交互验证：开始专注、暂停、继续、跳过休息、长按放弃、取消确认和确认放弃。
- 生命周期验证：切后台、熄屏、回到应用后剩余时间继续由引擎恢复。
- 编译验证：执行 `:app:compileDebugKotlin --no-daemon`；若本机 Gradle/Kotlin 缓存仍缺依赖，则记录为环境阻塞，不将其误判为功能代码错误。
